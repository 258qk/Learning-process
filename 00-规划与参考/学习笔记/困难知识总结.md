# 困难知识总结

记录学习过程中遇到的难以理解的知识点，便于复习回顾。

| 日期 | 知识点 | 困难描述 | 理解思路 | 解决方法 |
|------|--------|---------|---------|---------|
| 2026-06-07 | Python `for i in list` vs C `for(i=0;i<n;i++)` | 用 C 思维写成 `data_2[i] += 10`，但 `i` 是元素值而非下标，导致逻辑错误或越界 | Python 的 `for item in list` 遍历的是值，不是下标。需要下标时用 `for i in range(len(list))` 或 `for i, val in enumerate(list)` | 对比两种写法，理解每种适用场景：<br>• 只需值 → `for x in arr`<br>• 需下标 → `for i in range(len(arr))`<br>• 都需要 → `for i, x in enumerate(arr)` |
| 2026-06-08 | Python 列表切片 `[-n:]` vs `[0:-n]` | 想取最后 4 个元素写成了 `arr[0:-4]`，实际取出的是前 6 个 | `[a:b]` 是下标 a 到 b-1。`[-4:]` 表示"从倒数第4个取到末尾"；`[0:-4]` 表示"从开头取到倒数第4个（不含）" | 取最后n个 → `arr[-n:]`；丢弃最后n个 → `arr[:-n]` |
| 2026-06-08 | linspace 步长陷阱 | Python 手写 linspace 时用 `i * 2π / N`，最后一个点不等于终点值 | `linspace(起点, 终点, N)` 有 N 个点、N-1 个间隔。步长 = `(终点-起点)/(N-1)` 而非 `/N` | 类似 C 里数组下标差 1 的 off-by-one 错误 |
| 2026-06-08 | `np.mean(list)` 为什么能接收 Python 列表 | 以为 `np.mean()` 是 ndarray 的方法，疑惑为什么传入普通列表也能用 | `np.mean()` 是 NumPy 的**函数**（不是方法），接收任何数组类参数，内部自动做 `np.array(data)` 转换 | `np.mean(list)` ≈ `np.array(list).mean()`，NumPy 函数自动转换；但 `list.mean()` 不存在——列表没有这个方法 |
| 2026-06-08 | axis 方向判断 | reshape 后对 axis=0 和 axis=1 求均值，容易搞反方向 | axis=0 = 上下方向（列），axis=1 = 左右方向（行）。像 C 里的二维数组：axis=0 是第一维，axis=1 是第二维 | `arr.sum(axis=0)` = 沿着行方向求和（每列一个结果）；`arr.sum(axis=1)` = 沿着列方向求和（每行一个结果） |
| 2026-06-09 | `np.random` 是模块不是函数——为什么写 `np.random.randn()` 不写 `np.randn()` | `np.random` 里有很多随机方式，需要指定用哪一种 | `np.random` 是模块，里面装了 `randn`（正态分布）、`rand`（均匀分布）、`seed`（固定种子）等多个函数 | 类比 STM32：`USART_Init()` 和 `USART_SendData()` 都在 USART 模块下，不能单独写 `Init()` |
| 2026-06-09 | 传感器仿真——"递增"需要 `i × 步长` 而非每次加固定值 | 用 C 思维写成 `gps[i] = 31.23 + 0.00001`（每步加固定值），但位置没有累积 | 每采样点向北移动 = 位置持续增加。第 i 个点是 `31.23 + i × 0.00001`，不是 `31.23 + 0.00001`（每次都是同一个位置） | 类比积分：速度 × 时间 = 位移，这里步长 × 步数 = 位置。用 `arange(samples) * 步长` 一次性生成 |
| 2026-06-09 | `column_stack` 要求所有数组长度一致 | 把 1000 个点的数据和一个 60 个点的切片同时塞进 `column_stack`，报错 `dimension 0 mismatch` | `column_stack` 横向拼接，所有输入数组必须行数相同 | 切片统计单独打印，不要塞进 `column_stack` |
| 2026-06-09 | NuPy/库函数名称记不住，需要查旧代码 | 知道思路和逻辑（要用"拼数组存CSV"），但忘了函数名叫 `column_stack` 还是 `stack_columns` | 这不是没掌握——知道做什么 + 哪里查 = 正常。STM32 标准库的 `HAL_UART_Transmit` 也不是背的 | 用 20 遍自然记住。区分"不知道做什么"（严重）和"忘了具体函数名"（正常） |
| 2026-06-10 | 二维切片 `[行, 列]` 的起始位规则 | 知道 C 的 `for(i=0;i<n;i++)` 但转换到 Python 切片 `[a:b]` 时容易混淆"第几个"和"下标" | 起始位 = 第 N 个 - 1，停止位 = 最后一个想要的"第几个" | 第 2 到第 4 个 → `[1:4]`（不是 `[1:3]` 也不是 `[2:4]`） |
| 2026-06-10 | PyTorch 的 `dim=` 和 NumPy 的 `axis=` 是同一个东西 | 换成新库后不知道 `dim` 是什么意思 | PyTorch 用 `dim`，NumPy 用 `axis`，含义完全一样 | `tensor.mean(dim=0)` = `np.mean(arr, axis=0)` |
| 2026-06-10 | `numpy.tensor()` 不存在——Tensor → NumPy 用 `.numpy()` | 以为 NumPy 和 PyTorch 互转是双向对称的 | NumPy → Tensor：`torch.tensor(arr)`；Tensor → NumPy：`tensor.numpy()` | 记住方向：`torch` 负责创建，`.numpy()` 负责退回 |
| 2026-06-10 | autograd 全链路：requires_grad → backward → .grad | 不理解"为什么 grad 一定要先 backward 才有值" | requires_grad = 打开录音（只记录不计算），backward() = 倒着放录音算出导数 | STM32 类比：`ADC_Cmd(ENABLE)` 使能外设，`ADC_StartConversion` 才开始转换出数据 |
| 2026-06-10 | loss 计算必须在 no_grad 外，参数更新在 no_grad 内 | 把 loss = (w-0)² 写进 no_grad 里，backward() 找不到梯度图报错 | no_grad 关闭追踪 → loss 计算不会被录下来 → backward 找不到路 | 只有参数更新（w -= lr*grad）放 no_grad 里，loss 计算留外面 |
| 2026-06-10 | grad 累加机制 + zero_() 的作用 | 循环里忘记 zero_()，新旧梯度混在一起，更新方向错误 | PyTorch 的 .grad 默认是加法累加（+=），不清零会叠加 | 每条训练循环最后写 `w.grad.zero_()` |
| 2026-06-10 | `.item()` 取 Tensor 里的数字 / while 条件判断 | while lose != 0 报错，Tensor 不能直接和 int 比较 | Tensor 是容器，.item() 取出里面的 Python 数字 | 所有条件判断用 `.item()`：`while abs(w.item()-target) > 0.01` |
| 2026-06-10 | 梯度下降曲线绘制——记录时机 | 画出来的图是 0 值直线——zero_() 写在 append 之前，取到的永远是 0 | 先记录 grad 再清零 | `data.append(w.grad.item())` 在 `w.grad.zero_()` 之前 |
